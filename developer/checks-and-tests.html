检查与测试 ​

按修改范围选择检查 ​

以下命令在仓库根目录执行。先检查受影响部分，再根据变更范围补充相关检查。

修改范围命令
前端类型pnpm typecheck
前端格式与 Lintpnpm --dir frontend format:check、pnpm lint:frontend
Vue 规则与组件行为pnpm test:frontend
Rust 格式与 Lintpnpm format:backend:check、pnpm lint:backend
Rust 规则与模块协作pnpm test:backend
仓库启动、环境与打包脚本pnpm lint:scripts、pnpm test:desktop-scripts
前端导航与主题等浏览器流程pnpm test:e2e

pnpm check:all 顺序执行架构、SDK、格式、Lint、类型和测试检查，不执行生产构建。生产打包按构建说明在需要验证安装包时单独进行。

端到端测试配置指定 channel: 'chrome'，需要 Google Chrome。已有 Chrome 可直接运行；缺少时安装对应浏览器：

bash
pnpm --dir frontend exec playwright install chrome

浏览器测试使用模拟接口，原生托盘、通知、窗口和真实请求仍需桌面验证。

每个命令的执行范围、自动修复副作用、测试筛选示例和报告入口见开发命令参考。

架构与 SDK ​

bash
pnpm check:architecture
pnpm check:sdk

前者检查宿主产品模块与公共库依赖边界；后者检查 SDK API，并运行独立 SDK 消费者测试。修改公共接口、Cargo 依赖或源码模块路径时，应覆盖这两项。

站点策略和凭据校验应留在 backend/src/modules/sites/ 等产品业务模块中。公共 model-client 负责协议和通用 HTTP 输入校验，不应引入特定业务规则。涉及端点或记录时，要验证 Base URL + endpoint 原文一致，并检查 JSON/JSONL 中的地址与凭据脱敏结果。

测试放在哪里 ​

前端与 Rust 分别在 frontend/tests/、backend/tests/ 使用同一分类：

子目录内容
unit/单条规则或独立模块
integration/多模块协作与完整流程
support/测试夹具、替身和共享辅助函数

按测试行为命名文件，如 request_parameters.rs、concurrency.rs。Rust 的 mod.rs 用于组装测试套件。

Rust 模块私有行为仍通过所属模块挂载测试文件；backend/src/ 只保留必要的 #[cfg(test)] 与 #[path = "..."] 声明。不要为迁移测试而扩大生产 API 的可见性。

修改 antdv-next 组件 ​

项目要求先通过本地工具查询 API 和示例，再修改组件。例如使用 Button 时：

bash
.agents/bin/antdv info Button --format json
.agents/bin/antdv demo Button basic --format json

改动后对实际修改目录执行检查，例如：

bash
.agents/bin/antdv lint --cwd frontend/src/views/config --format json

使用项目内包装器，完整工作流以仓库 AGENTS.md 和 .agents/skills/antdv/SKILL.md 为准。
