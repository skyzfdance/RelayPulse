开发命令参考 ​

以下命令以当前仓库的根 package.json、frontend/package.json 和 scripts/ 为依据，均从仓库根目录执行。根脚本负责协调前端、Rust 和桌面包装器；文档站有独立依赖，使用 pnpm --dir docs/guide …。

安装依赖 ​

命令作用
pnpm install --frozen-lockfile按根锁文件安装仓库与前端工作区依赖；依赖声明与锁文件不一致时失败，不自动更新锁文件
pnpm --dir docs/guide install --frozen-lockfile单独安装文档站依赖；根工作区安装不包含文档站

工具版本及首次启动步骤见开发环境与源码运行。Rust 依赖由 Cargo 在相应检查、测试或桌面命令中下载和编译。

运行与预览 ​

命令作用与适用场景
pnpm dev:desktop启动 RelayPulse Dev、Vite 前端和真实 Rust 后端，支持开发热更新；用于托盘、窗口、通知及真实请求联调
pnpm dev:web只启动 Vite 前端；主窗口为 http://localhost:1421，小面板为 /panel，浏览器接口使用 mock
pnpm preview:web预览已经构建的 frontend/dist/development/，不会先执行构建，也不启动 Rust 后端；先运行 pnpm build:web，访问地址以终端输出为准
pnpm info:desktop输出 Tauri、系统、Rust、Node.js 及相关项目配置信息，用于排查工具链问题
pnpm tauri <子命令> [参数]经项目包装器调用本地 Tauri CLI；适合查看帮助或使用未单独封装的 Tauri 子命令

Vite 固定使用端口 1421，端口被占用时会失败。桌面启动会管理前端服务，切换 dev:desktop 与 dev:web 前先停止之前的启动命令。长时间运行的开发、预览和 watch 命令使用 Ctrl+C 停止。

macOS 开发启动会在 backend/target/development.noindex/macos-dev-runners/ 更新固定的 RelayPulse Dev.app，完成开发签名与系统注册后启动。该 runner 由包装器设置，不需要手动执行 Shell 脚本。

构建与产物 ​

命令执行内容产物或用途
pnpm build:web前端类型检查，再执行 Vite 构建frontend/dist/development/；用于网页资源验证，不生成桌面应用
pnpm build:assets:dev前端类型检查，并显式指定开发资源目录frontend/dist/development/；与桌面开发测试包的资源构建对应
pnpm build:assets:production前端类型检查，并显式指定正式资源目录frontend/dist/production/；与正式桌面包的资源构建对应
pnpm build:desktop:dev开发身份的前端构建、Rust 编译和 Tauri 打包RelayPulse Dev；输出根目录为 backend/target/development.noindex/
pnpm build:desktop:production正式身份的前端构建、Rust 编译和 Tauri 打包RelayPulse；输出根目录为 backend/target/production/

两种桌面构建默认都使用 Rust release 构建；命令中的 dev 表示开发应用身份，并不表示 debug 编译。macOS 包通常位于对应输出根目录的 release/bundle/app/、release/bundle/dmg/；指定目标架构后，中间还会增加目标三元组目录，以实际构建输出为准。

构建按需要单独执行，不把全部生产打包当作文档修改或日常检查的固定步骤。签名、公证、安装及环境隔离见构建与环境隔离。

Tauri 参数怎样传递 ​

附加参数直接跟在 pnpm 脚本名后面，例如：

bash
pnpm tauri --help
pnpm tauri dev --help
pnpm tauri build --help
pnpm dev:desktop --no-watch
pnpm build:desktop:dev --debug --no-bundle
pnpm build:desktop:production --target aarch64-apple-darwin --bundles dmg

前三条只显示帮助。后面三条分别用于关闭开发监听、编译开发身份的 debug 程序但跳过打包，以及构建指定架构的正式 DMG。构建示例会实际编译或打包，按当前任务选择执行。

参数适用命令说明
--no-watchdev:desktop / tauri dev禁用 Tauri 文件监听；不会关闭独立的 Vite 热更新
--releasedev:desktop / tauri dev以 release 编译模式运行，仍使用开发身份
--debugbuild:desktop:* / tauri build改用 debug 编译；不会改变所选应用身份
--no-bundlebuild:desktop:* / tauri build编译程序，跳过安装包生成
--target <目标>Tauri 开发或构建选择目标三元组；需要相应 Rust target 和平台工具链
--bundles app / --bundles dmgmacOS 构建选择生成的包类型，当前平台可用值见 tauri build --help
--productionpnpm tauri build / pnpm tauri bundle项目包装器的正式身份开关；build:desktop:production 已包含，不用于 dev 或 info

包装器禁止传入 --config、-c 等配置覆盖参数，也会清除外部 TAURI_CONFIG；即使 Tauri 自带帮助列出了它们，本项目也不允许通过它们切换身份。使用 --production 选择正式构建。其他 Tauri 参数是否可用，以当前安装版本的对应子命令帮助为准。

检查与自动修复 ​

命令检查或修改的内容
pnpm check:architecture读取 Cargo 工作区元数据与源码，检查宿主业务模块及六个公共 SDK 的依赖、源码引入边界
pnpm check:sdk对照 SDK 声明、序列化属性和共享 SQL 基线，再运行独立消费者测试；测试输出位于 backend/target/sdk-consumer/
pnpm typecheck顺序检查前端源码、前端测试和工具配置的 TypeScript 类型，不生成前端资源
pnpm lint:frontend前端 ESLint，包含 Vue、TypeScript 和工具配置；警告也视为失败
pnpm lint:scripts使用 scripts/eslint.config.js 检查仓库脚本；警告也视为失败
pnpm lint:backend对 Rust 工作区的所有 targets、features 执行 Clippy；警告也视为失败
pnpm lint依次执行前端、仓库脚本、Rust 三部分 Lint
pnpm lint:fix自动修复前端与仓库脚本的 ESLint 问题，会改写文件；不执行 Rust 自动修复
pnpm format:backend:check使用 rustfmt 检查整个 Rust 工作区的格式，不改写源码
pnpm format:check依次执行前端 Prettier 与 Rust 格式检查，不改写源码
pnpm format:backend使用 rustfmt 格式化 Rust 工作区，会改写文件
pnpm format依次格式化前端和 Rust，会改写文件；不格式化仓库脚本、README 或文档站
pnpm check:all依次执行架构、SDK、格式、Lint、类型、前端测试、Rust 测试、桌面脚本测试、端到端测试；任何一步失败即停止

check:all 不执行应用生产打包，但其中的 Cargo 检查和测试会编译 Rust。只改文档时，构建并检查文档站即可；代码变更按受影响范围选择检查，见检查与测试。

SDK 基线变更 ​

check:sdk 发现公共接口变化时会失败。确认接口变更符合预期、完成兼容性评估，并先单独通过消费者测试后，才更新基线：

bash
cargo test --manifest-path backend/tests/integration/sdk/Cargo.toml --target-dir backend/target/sdk-consumer
node scripts/check-sdk-api.mjs --update
pnpm check:sdk

--update 会改写 scripts/sdk-api.snapshot.json，需要连同接口变更一起审阅。不要仅为消除失败而重录基线。

测试命令 ​

命令覆盖范围与行为
pnpm test:frontend单次运行 Vitest，覆盖 Vue 单元、组件及前端模块协作测试
pnpm test:frontend:watch启动 Vitest 监听模式，修改文件后重新运行相关测试；Ctrl+C 退出
pnpm test:backend对 Rust 工作区启用全部 features，执行单元与集成测试
pnpm test:desktop-scripts使用 Node.js test runner 执行 scripts/tests/*.test.mjs，覆盖环境隔离、macOS runner、架构及 SDK 检查逻辑
pnpm test:e2e运行 Playwright，当前覆盖菜单、导航、404 和主题持久化；使用 mock 前端及 Chrome

运行受影响的测试 ​

以下示例直接调用测试工具，避免每次运行全部测试：

bash
pnpm --dir frontend exec vitest run tests/unit/config/sites/add-site-modal.test.ts
node --test scripts/tests/desktop-environment.test.mjs
cargo test --manifest-path backend/Cargo.toml -p relaypulse-storage --all-features

三个命令分别选择一个 Vue 测试文件、一个仓库脚本测试文件，以及一个 Rust 库包。测试目录约定见检查与测试。

Chrome 与端到端测试 ​

frontend/playwright.config.ts 指定 channel: 'chrome'，因此需要 Google Chrome。已有 Chrome 可直接运行测试；缺少时按环境需要安装：

bash
pnpm --dir frontend exec playwright install chrome
pnpm test:e2e

安装 Chromium 不能替代当前配置所要求的 Chrome。测试会启动 127.0.0.1:1421 的前端服务；非 CI 环境可复用已有服务，CI 环境不复用。失败截图与 trace 位于 frontend/test-results/，HTML 报告位于 frontend/playwright-report/。

bash
pnpm --dir frontend exec playwright show-report

该命令打开已有 HTML 报告，不重新运行测试。自动化脚本不覆盖原生托盘、窗口定位、系统材质、通知授权和真实服务商调用。

本地通知联调服务 ​

bash
node scripts/probe-notification-server.mjs

服务只监听 http://127.0.0.1:18081，Ctrl+C 停止。用于开发版验证故障与恢复通知，不访问真实服务商：

  1. 添加临时站点，协议选择 Anthropic，Base URL 填 http://127.0.0.1:18081，凭据填演示值 local-test。
  2. 获取并启用唯一模型 relaypulse-notification-test。
  3. 将连续失败转红和连续成功恢复都设为 1，并开启、授权相应通知。
  4. 暂停周期探测，手动发起正式探测，观察“正常 → 故障 → 恢复”的状态及通知。

服务从第一次生成请求开始交替返回成功 SSE 与 HTTP 503。读取模型目录不会推进顺序，但草稿试探、参与者预检等生成请求也会推进顺序；核对通知时避免交叉操作。该脚本没有端口参数，18081 被占用时会报错退出。

离线数据转换 ​

relaypulse-data-transfer 没有根 pnpm 别名，可通过 Cargo 运行：

bash
cargo run --manifest-path backend/Cargo.toml --bin relaypulse-data-transfer -- \
  --offline-source "/path/to/stopped-source" \
  --destination "/path/to/new-destination"

将示例路径替换为实际目录，带空格的路径保留引号。-- 后的两个参数及顺序固定：源应用必须已经停止，目标必须不存在且父目录存在，源与目标不能相互包含。命令向目标写入备份、转换数据和校验报告，不自动激活数据目录。

退出码 0 表示成功；参数错误为 2，转换或校验失败为 1。失败时保留源数据，不能启用未经成功校验的目标；完整约束见数据存储与升级机制。

antdv-next 查询与检查 ​

前端组件修改前先查询实际组件的 API 和示例，修改后检查对应目录：

bash
.agents/bin/antdv info Button --format json
.agents/bin/antdv demo Button basic --format json
.agents/bin/antdv lint --cwd frontend/src/views/config --format json

info 查看组件 API，demo 获取示例，lint 检查组件用法。将 Button 和目录替换为实际对象；使用项目包装器，不安装全局 CLI，也不执行其 init、setup 或 upgrade。

包装器由本地 .agents/ 配置提供，不随主分支克隆。新环境缺少该文件时，先取得项目使用的本地工具配置。

文档站命令 ​

文档站位于被 Git 忽略的 docs/guide/，独立于应用工作区，不随主分支克隆。维护站点前需取得另行保留的文档源文件；GitHub Pages 上的静态网页不包含这些编辑源文件。构建只读取 content/ 中的公开页面和资源，不发布本地工程笔记及采集材料。

命令作用及副作用
pnpm --dir docs/guide dev在 http://127.0.0.1:4175/RelayPulse/ 启动文档开发服务，编辑后热更新
pnpm --dir docs/guide build构建静态站点到 .vitepress/dist/，随后校验本地资源、页面链接、锚点及页面数量；不会构建桌面应用
pnpm --dir docs/guide check只校验上一次构建的产物；不会先构建，正文修改后应先运行 build
pnpm --dir docs/guide preview在 4175 端口预览已有静态产物；先停止 dev，重新构建后需要重启预览服务
pnpm --dir docs/guide pages:prepare构建、校验、更新 .pages/ 并加入 .nojekyll，不创建 Git 提交或推送
pnpm --dir docs/guide pages:publish构建、校验，并将静态站点提交、推送到配置仓库的 gh-pages 分支；会替换该分支网页文件

发布使用本机项目的 Git 提交身份与远端推送权限，不切换主工作区分支、不强制推送，也不会把忽略的 Markdown 加入主分支。pages:publish 会创建提交，执行前遵守仓库审阅约定；首次还需在 GitHub Pages 设置 gh-pages / 根目录。首次设置及本地源文件备份方式见本地 docs/guide/维护与发布.md。
