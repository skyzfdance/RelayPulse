## 1. 开发目标

建立可在 macOS、Windows 和冻结 Linux 环境运行的 Tauri 2 桌面壳，用类型化 mock data source 完整实现九个定稿 view。交付物首先证明 UI、交互、托盘和窗口体验成立；后端阶段只需实现新的 data source adapter，不改变页面结构和交互契约。

## 2. 实施原则

### 2.1 UI 是第一交付层级

主窗口与托盘界面不等待数据库、探针或调度器。所有需要的产品状态先由确定性 fixture 表达并独立验收。

### 2.2 壳是真实的，业务数据是 mock 的

窗口、托盘、单实例和显式退出使用真实 Tauri/Rust 能力；站点、模型、耗时、错误和设置使用 mock adapter。

### 2.3 页面不感知后端实现

组件只使用 `RelayPulseDataSource` 和领域 DTO。禁止页面直接调用 `invoke`、访问网络或写本地存储。

### 2.4 单一组件体系

使用 Ant Design、Design Token 和 CSS Modules。只有定稿无法由现有组件合理表达时才创建项目内组件，不引入第二套 UI 库。

### 2.5 交互与测试同行

每个 view 同时完成 loading、empty、error、键盘操作、组件测试和固定 fixture；TASK-05 只闭合跨页面和跨平台证据。

## 6. 核心实施契约

### 6.1 技术栈与库

**生产依赖**

| 范围 | 库 |
|---|---|
| 桌面 | `tauri`、`@tauri-apps/api` |
| 壳层插件 | `tauri-plugin-single-instance`、`tauri-plugin-positioner` |
| 可选真实开机启动 | `tauri-plugin-autostart`，仅 D05 明确纳入时安装 |
| 前端 | `react`、`react-dom`、`typescript`、`vite` |
| UI | `antd`、`@ant-design/icons` |
| 排序 | `@dnd-kit/react`、`@dnd-kit/helpers` |
| Rust DTO/错误 | `serde`、`serde_json`、`thiserror`，只服务壳层消息 |

**开发依赖**

- Vitest、Testing Library、`@testing-library/user-event`。
- Playwright。
- ESLint、Prettier、TypeScript 编译器。
- Rustfmt、Clippy 和 Rust 内置测试框架。

**明确不引入**

- SQLx、SQLite/Tauri SQL、Store 作为业务持久化。
- Reqwest、真实 HTTP/SSE、协议 SDK。
- keyring、Stronghold 或其他 CredentialStore。
- Redux、Zustand、React Query；当前状态用 Context + `useReducer`，未来有实际复杂度再决策。
- 第二套 UI 库、图表库、CSS 框架和自绘图标库。

### 6.2 View 与 fixture

- `?view=<name>` 能确定性进入九个验收状态；未知值回退到 `sites`，无站点 fixture 进入 `empty`。
- fixture 与 view 名分离：同一 view 可以切换 healthy、loading、error、long-text 等辅助场景。
- fixture 数据必须稳定，不使用当前时间、随机 ID 或网络结果生成视觉内容。
- 生产导航可以使用应用状态，但不得破坏 view 验收入口。

### 6.3 Data source

`RelayPulseDataSource` 负责站点、模型、通用设置和托盘快照的读取/命令语义；页面组件不区分 mock 和未来 Tauri adapter。

- 所有方法异步返回，以暴露 loading 和失败状态。
- mock 支持可控延迟和错误注入，但自动化使用虚拟时钟或显式 promise，不用随机 sleep。
- 保存、取消和删除只改变内存快照；重载 fixture 可恢复。
- DTO 不包含真实 Secret；Key 字段仅允许草稿和掩码状态。

### 6.4 窗口与托盘

- `main` 窗口承载七个主窗口 view；`tray-panel` 窗口承载两个托盘 view。
- 关闭主窗口只隐藏窗口；托盘菜单“退出”才结束进程。
- 第二次启动聚焦已有主窗口，不创建第二套 mock 状态。
- 面板必须位于托盘附近且处于可见工作区；无法稳定悬停的平台使用点击或菜单。
- 不在页面内部绘制操作系统窗口控制。

### 6.5 交互和样式

- Ant Design `ConfigProvider` 固定主题 token、语言和组件密度。
- Modal/Drawer 的遮罩覆盖标题栏以下全部应用区域，包括左侧菜单；背景不可交互。
- 站点排序支持指针和键盘；取消拖动恢复原顺序。
- 表单具有 label、错误、disabled、loading、保存成功和离开未保存状态。
- 图标只来自 `@ant-design/icons` 或平台托盘资源；不手绘等价 SVG。
- 长站点/模型名不得挤压双耗时和操作列；采用稳定列宽、省略和可访问全名。

## 7. 编号任务实施

### TASK-01 Tauri 跨平台桌面壳

**目标**

交付可构建、可启动、可显式退出的 Tauri 2 壳，并关闭平台和托盘路径的关键不确定性。

**前置依赖与决策门**

- 计划评审通过，D05 已确认。
- D01、D02 在任务退出前关闭。

**实施内容**

1. 初始化 Rust、Tauri 2、React/TypeScript/Vite 和 pnpm 工程，提交锁文件和工具链配置。
2. 建立 `main`、`tray-panel` 两个窗口，托盘资源、菜单、显示/隐藏和显式退出。
3. 接入 single-instance 和 positioner，最小化 capabilities 权限。
4. 在三个目标环境验证构建、启动、关闭窗口继续运行和第二次启动。
5. 为后续 UI 提供可切换的空白 view 和壳层事件入口。

**交付物**

- 可运行工程、Tauri 配置、两窗口壳、托盘资源、权限清单和锁文件。
- D01 平台矩阵、D02 行为表和三平台冒烟入口。

**关联测试**

- T-SHELL：SHELL-001 至 SHELL-008。

**退出检查**

- 声明平台均可构建启动；托盘和两个窗口路径可达。
- 关闭窗口不退出，显式退出无残留进程，单实例生效。
- D01、D02 有唯一结论。

### TASK-02 UI 基础与数据边界

**目标**

建立统一视觉基础、确定性 view/fixture、领域 DTO 和可替换 data source，并用代表 view 验证技术路线。

**前置依赖与决策门**

- D03、D04 在任务退出前关闭。

**实施内容**

1. 配置 Ant Design `ConfigProvider`、主题 token、CSS Modules、字体、密度和响应式边界。
2. 建立应用布局、`view` 解析、错误边界和页面 loading/empty/error 骨架。
3. 定义 DTO、`RelayPulseDataSource`、mock adapter、fixture 和可控错误。
4. 实现 `sites`、`model-settings`、`tray-alerts` 三个代表 view，验证复杂表格、抽屉和紧凑面板。
5. 建立 Vitest、Testing Library、Playwright 和视觉截图入口。

**交付物**

- UI shell、主题、共享组件、data source、fixture、三个代表 view 和测试配置。
- D03 截图对比、D04 组件适配结论。

**关联测试**

- T-FOUNDATION、T-MOCK、VISUAL-001、VISUAL-004、VISUAL-009。

**退出检查**

- 页面不直接调用 Tauri、网络或本地存储。

- D03、D04 有唯一结论，技术路线无需第二套 UI 库。

## 9. 开发过程规则

1. 任务开始前确认前置任务和要求“开始前”关闭的决策门。
2. 每个 view 同行交付 fixture、交互、组件测试和视觉入口。
3. mock 操作必须在 UI 或开发模式中可识别，不得声称已连接真实后端。
4. 页面不得绕过 data source；壳层权限不得为了未来可能需求提前扩大。
5. 依赖版本由 `pnpm-lock.yaml`、`Cargo.lock` 和工具链文件冻结，不在文档中追逐小版本。
6. 视觉基线变化必须由用户重新确认，并同步定稿索引、测试和验收方案。
7. 任务状态只根据实际交付物、测试和退出证据更新。
