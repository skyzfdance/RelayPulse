# RelayPulse MVP 01 测试用例

> 状态：草案，待开发计划验收
>
> 对应计划：[RelayPulse MVP 01 开发计划](./开发计划.md)
>
> UI 基线：[RelayPulse UI 定稿索引](../../design/final/README.md)
>
> 原则：只验证 Tauri 桌面壳、UI、mock data source 和九图视觉；不验证尚未实现的后端能力。

## 1. 测试目标

- 证明三平台 Tauri 壳、托盘、窗口、单实例和退出语义成立。
- 证明九个 view 能由确定性 fixture 独立进入，页面不依赖真实后端。
- 证明七个主窗口状态及其表单、排序、启停、弹窗和抽屉交互符合定稿。
- 证明健康/异常托盘面板的内容、Top 3、双耗时和平台触发符合定稿。
- 证明 loading、empty、error、长文本、键盘和缩放状态不破坏布局。
- 证明 UI 只通过 `RelayPulseDataSource` 取数，没有网络、数据库、Secret 或隐式持久化。
- 证明候选版本的九图报告、测试和三平台壳层结果可复核。

## 3. 公共测试条件

### 3.1 Fixture 与数据

- fixture 仅使用虚构站点、模型、状态、耗时和掩码 Key。
- fixture ID、排序、时间显示和文本固定，不使用随机数、当前时间或网络。
- mock data source 支持 success、loading、empty、error 和长文本模式。
- 每个测试重置内存状态；不得依赖 `localStorage`、IndexedDB、SQLite 或 Tauri Store。

### 3.2 View 与视口

- 九个 fixture 名与 `view` 参数一致。
- 主窗口视觉视口以定稿图尺寸 `1504 x 964` 为基准；托盘健康 `480 x 400`，托盘异常 `520 x 520`。
- 同时检查最小支持窗口、125%/150% 缩放和长中英文文本。
- 视觉比较排除操作系统原生窗口边框；应用内容、布局、状态色、文案和遮罩参与审查。

### 3.3 平台矩阵

- macOS、Windows 和 D01 冻结的 Linux 必选环境都执行 Tauri 壳层冒烟。
- Linux 按 D02 使用悬停、点击或菜单中的已确认路径。
- 九图像素基准可在一个冻结 WebView 环境生成，其他平台执行布局/交互审查，不强求原生字体逐像素一致。

## 12. 自动化位置约定

- 前端单元/组件测试与源码同目录或置于 `src/**/__tests__/`。
- Playwright E2E 置于 `tests/e2e/`，视觉入口置于 `tests/visual/`。
- Rust 壳层测试置于 `src-tauri/src/` 对应模块或 `src-tauri/tests/`。
- 候选报告输出到未跟踪的统一 artifacts 目录；确认后只登记脱敏摘要和证据索引。
- 视觉失败不得通过无条件更新快照解决，必须说明定稿变更或实现修复。

## 13. 测试通过标准

- P0、P1 用例全部通过；P2 失败有影响评估。
- 九个 view 均有当前候选截图、diff 和人工审查结论。
- 声明的 macOS、Windows、Linux 环境均通过壳层构建和核心生命周期冒烟。
- 没有真实 Secret、外部请求、业务数据库或后端依赖进入测试和制品。
- 不用随机 sleep、当前时间或外部网络决定断言。
- 文档校验无 ERROR，WARN 已逐项处理或说明。
