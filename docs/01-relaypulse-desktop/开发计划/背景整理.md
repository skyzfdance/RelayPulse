# RelayPulse MVP 01 背景整理

> 状态：草案，待开发计划验收
>
> 整理日期：2026-07-29
>
> 说明：本文只记录桌面壳与 UI 阶段的已确认基线、仓库事实、外部约束和待取证事项。

## 1. 整理目的

RelayPulse 的完整产品需要本地数据、Secret、探针和调度能力，但用户已明确实施顺序为“先确定 UI，再写后端”。因此 MVP 01 必须形成一个真实运行在 Tauri 中、可独立验收的 UI 层，同时用稳定接口隔离未来后端，不能把静态网页原型或临时持久化当成阶段交付。

## 2. 已确认的实施基线

- 第一层级只交付 Tauri/Rust 桌面壳和 UI，不实现真实业务后端。
- 目标平台为 macOS、Windows 和 Linux；平台触发方式可以不同，界面内容和状态语义一致。
- 主窗口共七个 view，托盘面板共两个 view；唯一视觉基线为 [UI 定稿索引](../../design/final/README.md)。
- 主窗口表达多站点、启停、优先级、模型推理与透传参数、通用设置和删除确认。
- 托盘健康状态保持极简；异常状态最多展示 3 个模型和首 Token/总耗时。
- 当前 UI 使用 mock 数据；后端通过 `RelayPulseDataSource` adapter 接入，不重写页面。
- 技术基线为 Tauri 2、Rust stable、React、TypeScript、Vite 和 Ant Design。
- 本阶段不使用 SQLite、系统凭据库、真实 API 请求、协议解析、调度或状态聚合。

## 4. 可参考但不直接迁移的内容

- [Tauri 2 系统托盘文档](https://v2.tauri.app/learn/system-tray/)用于建立壳层，仍需目标平台实测。
- [Tauri 插件目录](https://v2.tauri.app/plugin/)用于确认 single-instance、positioner 和 autostart 的支持范围。
- [Ant Design React](https://ant.design/docs/react/introduce)提供基础组件、Token 和交互语义；定稿 PNG 高于组件默认样式。
- [dnd kit React](https://dndkit.com/react/quickstart/)用于站点拖动排序，并要求同时支持键盘操作。
- [Playwright 组件测试](https://playwright.dev/docs/test-components)说明真实浏览器交互和视觉回归能力；本项目仍以固定 view 页面执行截图为主。
- 原型的 fixture 和页面结构可以参考，但生产 UI 必须按组件、状态和 data source 边界重建。

## 6. 当前计划假设

1. 首批只支持 64 位桌面系统，精确范围由 D01 决定。
2. Tauri 主进程存活时托盘继续存在；关闭可见窗口不等于退出应用。
3. Linux 可以使用点击或托盘菜单替代悬停，但两个托盘 view 的内容不变。
4. mock 数据只驻留内存；刷新恢复 fixture 是预期行为，不是数据丢失缺陷。
5. 只使用 Ant Design 作为组件体系，通过 Design Token、CSS Modules 和少量项目组件贴合定稿。
6. React Context + `useReducer` 足以管理本阶段 UI 状态；出现可证明的跨窗口状态复杂度后再评审状态库。
7. `view` 查询参数只服务于开发和验收入口，不等同于最终用户导航结构。
8. 规划不固定依赖小版本；初始化时锁定兼容版本并提交锁文件。
