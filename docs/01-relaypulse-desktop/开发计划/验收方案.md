# RelayPulse MVP 01 验收方案

> 状态：草案，待开发计划验收
>
> 验收对象：冻结的 RelayPulse 桌面壳与 UI 候选
>
> 明确排除：SQLite、CredentialStore、真实模型请求、探针调度和真实状态聚合

## 1. 验收目标

独立证明 RelayPulse 已形成可运行的 Tauri/Rust 桌面壳，九个定稿 UI 状态已经以生产组件实现，主要交互由确定性 mock data source 驱动，并且后端阶段能够沿稳定接口接入而不重写页面。

## 2. 验收角色

| 角色 | 职责 |
|---|---|
| 开发执行人 | 冻结候选、依赖、fixture、构建和自动化报告 |
| 验收执行人 | 在干净环境独立执行 AC-01 至 AC-05并收集证据 |
| 方案确认人 | 审查九图差异、平台降级和范围边界，给出最终结论 |

同一人可兼任，但执行记录必须区分角色结论。

## 3. 候选版本冻结

验收前冻结并记录：

- 源码提交、工作区状态和候选标识。
- `pnpm-lock.yaml`、`Cargo.lock`、Rust toolchain 和 Node/pnpm 版本。
- Tauri 配置、capabilities、插件与三平台构建摘要。
- 九个 fixture、view 映射、视口、字体、DPI 和主题配置。
- 三平台壳层制品或可复现构建入口。
- 九张基线图片的摘要和候选截图/diff 报告。

冻结后修改源码、依赖、fixture、Tauri 配置或样式必须生成新候选并重验受影响场景。

## 4. 验收环境

### 4.1 必需组件

| 组件 | 要求 |
|---|---|
| macOS | D01 冻结版本与架构，可从干净环境启动 Tauri 壳 |
| Windows | D01 冻结版本与架构，具备目标 WebView2 环境 |
| Linux | D01 冻结发行版/桌面环境，具备 WebKitGTK 与托盘依赖 |
| UI fixture | 当前候选内置固定 success/loading/empty/error/long-text 数据 |
| 视觉环境 | 冻结浏览器/WebView、视口、DPI、字体和主题 |
| 自动化 | 可执行前端、Rust、Playwright 和三平台构建命令 |

### 4.2 安全与隔离

- 不提供真实 API Key、外部模型站点或客户数据。
- 验收机器使用新应用数据目录，不依赖开发者本机缓存。
- 网络可以断开；核心 UI 验收不得访问外部服务。
- 截图、日志和报告只包含虚构 fixture。

## 5. 验收前置检查

1. 候选冻结信息完整，工作区差异有说明。
2. TASK-01 至 TASK-05 均具有退出证据并处于待验收或完成状态。
3. D01-D06 均关闭；D06 指向当前九图定稿索引。
4. P0/P1 自动化报告无失败。
5. 三平台壳层构建结果和九图候选截图齐备。
6. 依赖和 capabilities 审查确认没有后端库或越界权限。
7. 验收记录仍为未执行状态。

任一前置检查不满足，不开始正式验收。

## 8. 详细验收步骤

### AC-01 Tauri 三平台壳

**前置条件**

- 三个平台均使用当前候选构建；按 D02 准备对应托盘触发路径。

**步骤**

1. 在 macOS、Windows 和冻结 Linux 环境启动应用。
2. 检查托盘和主窗口，关闭主窗口后从托盘重新打开。
3. 打开并关闭托盘面板，改变显示器/缩放后再次打开。
4. 应用运行时再次启动，确认只保留一个实例。
5. 使用托盘菜单明确退出，检查进程收敛。
6. 查看 capabilities 和插件清单。

**通过标准**

- 壳层行为符合 D01/D02；面板不离屏；无伪系统窗口控制。
- 关闭窗口不退出，显式退出完整收敛，单实例成立。
- 权限只覆盖窗口、托盘、单实例和定位等本阶段能力。

**证据**

- 每个平台的构建摘要、进程摘要、录屏、窗口位置摘要和权限清单。

### AC-02 UI 数据边界

**前置条件**

- 使用固定 fixture，禁用外部网络，清空应用数据目录。

**步骤**

1. 依次打开九个 view 和未知 view。
2. 切换 success、loading、empty、error 和 long-text fixture。
3. 执行保存、排序、删除、retry 并重载应用。
4. 检查页面调用、生产依赖、Tauri capabilities 和运行网络请求。
5. 检查 fixture、日志和截图中的敏感模式。

**通过标准**

- 九个 view 可确定性进入；错误可恢复；重载恢复 fixture 初始状态。
- 页面只依赖 `RelayPulseDataSource`，没有直接 `invoke`、fetch、本地持久化或 Secret。
- 没有 SQL、HTTP、CredentialStore、图表或第二 UI 库进入当前制品。

**证据**

- Playwright trace、架构/依赖审查、capabilities、网络摘要和 fixture 扫描结果。

### AC-03 七个主窗口定稿旅程

**前置条件**

- 准备七个主窗口 fixture 和固定视觉环境。

**步骤**

1. 从 empty 添加站点，返回 sites 后拖动优先级并切换站点/模型启用。
2. 打开 site-advanced，验证校验、保存和取消。
3. 打开 model-settings，配置推理策略和透传参数，核对请求预览。
4. 修改 general；打开 delete-confirm 分别执行取消和确认。
5. 检查 Modal/Drawer 遮罩、阴影、焦点、长文本和缩放。
6. 生成七张候选截图和 diff。

**通过标准**

- 七个 view 的结构、文案、控件、状态、遮罩和信息层级符合定稿。
- 主要交互在 mock 下完整，取消可恢复；模型首列是启用开关。
- 无图表、营销页面、伪窗口三点或无功能入口。

**证据**

- 七张候选截图/diff、完整旅程录屏、Playwright trace 和可访问性摘要。

### AC-04 两个托盘定稿旅程

**前置条件**

- 准备健康 fixture 和至少 5 个异常模型的 fixture。

**步骤**

1. 打开 `tray-healthy`，检查摘要、计数和时间。
2. 打开 `tray-alerts`，检查前三条、异常总数、站点、首 Token 和总耗时。
3. 切换图标状态，执行 mock 刷新和打开设置。
4. 使用长文本、不可测量值、键盘和缩放检查布局。
5. 在三平台执行 D02 触发路径。
6. 生成两张候选截图和 diff。

**通过标准**

- 健康面板不显示模型列表；异常面板最多 3 条且双耗时对齐。
- 所有状态明确来自 fixture，不宣称真实探针已运行。
- 三平台入口可达，面板不闪烁、不离屏。

**证据**

- 两张候选截图/diff、三平台触发录屏、状态切换 trace 和焦点摘要。

### AC-05 UI 候选冻结

**前置条件**

- AC-01 至 AC-04 已执行，全部自动化和九图报告齐备。

**步骤**

1. 核对源码、锁文件、Tauri 配置、fixture、制品和报告候选标识。
2. 复核 P0/P1、九图 9/9、可访问性和三平台壳层结果。
3. 检查所有入口和依赖，确认后端范围未进入生产路径。
4. 运行文档结构校验并核对 AC 与验收记录一一对应。

**通过标准**

- 全部证据绑定同一候选，无未说明工作区或配置变化。
- 九图、主要旅程、可访问性和三平台壳层门槛全部通过。
- 后端阶段可以实现 adapter 接入，无需改变页面的数据调用方式。

**证据**

- 候选清单、测试汇总、九图报告、范围审查和文档校验输出。

## 9. 自动化结果复核

验收者必须记录命令、退出码、总数、通过/失败/跳过数和报告位置，至少覆盖：

- Rust fmt、Clippy、test 和 T-SHELL。
- TypeScript typecheck、ESLint、Vitest/Testing Library。
- Playwright T-JOURNEY、T-ACCESSIBILITY 和九个 view。
- 三平台 release 构建与壳层冒烟。
- 依赖/capabilities/敏感 fixture 扫描。
- MVP 文档结构校验。

## 10. 失败处理与复验

1. 在验收记录登记候选、AC、实际结果、问题编号和证据。
2. 壳不可用、主要旅程中断、页面绕过 data source、九图关键信息缺失或 P0/P1 失败均阻塞。
3. 平台原生字体差异只有 D03 和方案确认人认定不影响布局时才可排除。
4. 修复后生成新候选并重验受影响场景，不复制旧截图冒充新证据。
5. 若失败证明 D01-D05 不成立，返回对应决策门或阶段方案。

## 11. 环境清理与回退

- 删除临时应用数据、测试制品、Playwright trace 和未保留截图；只保留脱敏报告。
- 失败候选不得覆盖已验收候选；尚无已验收版本时只用于复现。
- 黄金图片只有用户重新定稿后才能更新。
- 本阶段没有数据库、凭据和外部测试站点需要清理。

## 12. 最终判定

- **通过**：P0/P1、AC-01 至 AC-05、九图 9/9、三平台壳层、范围审查和证据完整性全部通过。
- **不通过**：任一阻塞用例/AC 失败，九图漂移未确认，后端范围越界，或证据无法绑定当前候选。
