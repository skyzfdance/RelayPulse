常见问题 ​

添加站点时为什么连接失败 ​

按顺序检查：

  1. 接口协议是否与服务商说明一致。
  2. 对照请求地址预览，检查 Base URL 与端点直接拼接后是否与服务文档一致。
  3. API Key 是否有效，是否有读取模型目录的权限。
  4. 服务商是否支持当前模型列表端点；需要时在添加窗口或高级设置中按文档修改。
  5. 该服务是否需要特殊路径或附加请求头。

模型列表获取失败不会阻止保存站点。你可以保存后调整模型列表端点并重新同步，也可以手动添加模型。端点和协议请求字段按配置原文发送；如果服务商要求额外字段，请在探针策略的请求头或请求体中设置。

为什么没有自动探测 ​

检查应用是否仍在运行，并依次确认：

  1. “配置 → 通用设置 → 关闭主窗口后继续运行”已开启。
  2. 该站点开关已开启。
  3. 至少一个模型的探测开关已开启。
  4. 已等待站点“高级设置”中的探测间隔。
  5. 当前站点没有被同步、试探或其他任务占用。

小面板底部的下次时间可以辅助判断。后台开关关闭时，即使主窗口打开也不会安排新的自动探测；退出应用后也不会继续工作。

为什么 HTTP 200 仍显示探测失败 ​

常规模型探测还要检查有效回答和协议完成标记。空回答、只有思考文本、被截断或缺失完成标记，都可能导致失败。

打开“运行 → 探测记录”的详情，查看原始返回。确认请求协议正确，再按服务商要求调整 Token 上限、推理参数或流式设置。自定义 HTTP 使用不同的判定口径，见探针配置。

为什么有失败记录，小面板还没转红 ​

记录是单次请求的结果，小面板按连续失败、连续恢复规则显示稳定状态。新建站点默认连续失败 3 次转红，转红后连续成功 2 次恢复。

已有稳定状态时，未达到失败阈值前会保留之前的状态；尚无稳定状态且失败未达到阈值时显示“待确认”。首次成功可直接显示正常或偏慢。

为什么首 Token 或 Token 用量是横线 ​

  • 非流式或自定义 HTTP 请求不提供首 Token 耗时。
  • 没有收到可计时的有效文本时，首 Token 可能缺失。
  • 服务商没有明确上报 usage 时，Token 用量缺失。

横线 — 表示没有数据，不表示零耗时或免费。用量不完整时，以服务商后台和账单为准。

为什么模型操作按钮不能点击 ​

先检查站点基本信息是否有未保存更改，保存后再操作模型。再确认该站点是否正在探测、同步、试探或保存。同一站点的任务会互斥，等待当前任务结束后重试。

试探通过了，为什么记录里没有结果 ​

模型自定义请求中的“试探一次”验证的是当前草稿，不写入正式探测历史，也不自动保存设置。点击“保存”后，再发起一次正式探测。

为什么小面板只显示三个模型 ​

小面板最多展示 3 个模型，并按站点顺序组织。点击“查看全部”到站点管理查看其余模型；需要改变优先显示的站点时，可以调整站点顺序。

为什么收不到通知 ​

先检查“启用消息通知”、对应规则开关和系统权限，再发送测试通知。已授权但仍没有通知时，检查 macOS 通知设置与专注模式。

模型故障和恢复通知依据稳定状态变化，未达到阈值的单次失败不会立即发送。

为什么智商测试不能开始 ​

至少选择一道启用的题目，添加一个参与者，并确认所有参与者预检为“可用”。失败重试次数须为 0–20 的整数。

没有候选模型时，先去站点管理启用模型；预检失败时查看提示、调整配置，再重新探测或重新添加参与者。

智商测试显示成功，是答对了吗 ​

成功表示请求完成，不是答案判分。请结合题面、参考答案和输出回放人工判断。失败重试针对请求报错，不针对答案正确与否。

升级后要求迁移，应该怎么做 ​

按本地数据与版本升级使用“备份并迁移”。迁移期间保持应用运行；有失败提示时保留原数据与错误信息。

怎样反馈问题 ​

记录应用版本、macOS 版本、问题发生时间、操作步骤、预期结果和实际错误。需要排查日志时，在“配置 → 通用设置”导出诊断包。

可通过 GitHub Issues反馈。截图前隐藏 API Key 等凭据；涉及模型输出或题目内容时，确认哪些内容适合公开。
