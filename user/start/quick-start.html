完成第一次探测 ​

目标是添加一个站点、启用一个模型，并在小面板和探测记录里找到结果。

1. 准备连接信息 ​

从模型服务商处确认三个信息：接口协议、服务地址、API Key。优先使用服务商明确支持的协议。

选择协议后，添加窗口会把模型列表和探测端点预填为该协议的常用值，例如 /models 与 /chat/completions。这些字段可以修改；自定义 HTTP 没有固定端点，需要按服务文档填写。新建站点默认在小面板中隐藏。

留意地址中的路径

请求地址是 Base URL 与端点原文直接拼接，不会补斜杠或 /v1。例如 https://api.example.com 加 /models 得到 https://api.example.com/models；请在预览中确认地址与服务文档一致，详见地址填写说明。

2. 添加站点 ​

  1. 打开“配置 → 站点管理”。
  2. 点击“添加第一个站点”；已有站点时，点击左侧站点列表上方的加号。
  3. 填写站点名称、接口协议、Base URL 和 API Key。
  4. 如需在小面板显示该站点，主动勾选“在小面板中显示”。
  5. 点击“连接并获取模型”，等待站点创建和模型列表读取完成。

站点会先保存；模型列表获取失败时仍可在高级设置中调整端点后重试，或手动添加模型。

3. 选择要探测的模型 ​

在模型列表中找到需要监测的模型，打开该模型的探测开关。第一次使用先选择一个，确认成功后再增加。

模型不在列表中时，可以点击“添加模型”并输入服务商提供的完整模型标识。能手动添加并不代表该模型一定能被当前 API Key 调用，仍需通过探测验证。

4. 发起正式探测 ​

点击模型行的“立即探测模型”图标。若要探测当前站点所有已启用模型，点击“探测已启用模型”。

等待请求结束，然后前往“运行 → 探测记录”，查看对应模型的最新一条记录。这里可以确认本次请求是成功、偏慢还是失败，以及实际耗时。

若出现失败，打开记录详情，检查 HTTP 状态、错误提示、请求端点和原始返回；排查路径见常见问题。

5. 在状态栏查看结果 ​

点击 macOS 状态栏中的 RelayPulse 图标打开小面板，查看模型状态和“首 Token / 总耗时”。

  • “正常”：模型已达到健康判定要求，本次有效结果未达到慢阈值。
  • “偏慢”：请求成功，但首 Token 或总耗时达到设置的慢阈值。
  • “待确认”：已有结果，尚未达到稳定健康状态的判定阈值。
  • “不可用”：连续失败已达到转红阈值。

一次请求失败和模型被判定为不可用是两件事。

本次结果在记录里查看；稳定状态在小面板查看，具体规则见状态判定。

6. 保持周期探测 ​

在“配置 → 通用设置”保持“关闭主窗口后继续运行”开启，同时保持站点和模型启用。自动探测默认间隔为 300 秒，可在站点“高级设置”中调整。

小面板底部显示下次探测时间，说明周期探测已安排；显示“未启用周期探测”时，按自动探测排查检查。
