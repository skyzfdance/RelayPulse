探针配置与状态判定 ​

入口：配置 → 站点管理 → 选择站点。连接、频率和健康阈值在“高级设置”里，请求内容在“默认探针策略”或“模型探针设置”里。

设置探测频率和健康阈值 ​

点击“高级设置”，调整后点击抽屉中的“保存”。

配置新建站点默认值可填范围含义
探测频率300 秒1–86400 秒每个已启用模型自动探测的间隔
首 Token 慢阈值5 秒1–100 秒流式请求首 Token 达到此值时判为偏慢
总耗时慢阈值30 秒1–500 秒请求成功但总耗时达到此值时判为偏慢
连续失败转红3 次1–10 次连续失败达到此次数后判为不可用
连续成功恢复2 次1–10 次从不可用状态恢复需要的连续成功次数

慢阈值用于判断“偏慢”，达到慢阈值不会中断请求。偏慢仍属于成功响应，参与连续成功计数。数值输入须为整数。

自动探测需要同时满足：应用在运行、通用设置“关闭主窗口后继续运行”开启、站点启用、模型启用。关闭开关会停止后续派发，已经发出的请求会正常结束并保存结果。

编辑站点默认请求 ​

  1. 在站点详情的“默认探针策略”区域，点击“编辑默认值”。
  2. 在请求参数表中调整要发送的字段、值、类型和启用状态。
  3. 检查请求预览，点击“保存”。

继承站点默认的模型会使用这套请求。已经配置独立策略或自定义请求的模型按自己的配置执行。

给单个模型配置请求 ​

在模型行打开“模型探针设置”。

  • 普通独立策略：关闭“自定义探针请求”，编辑当前模型的请求参数并保存。保存后，该模型使用独立策略。
  • 自定义请求：打开“自定义探针请求”，填写自定义探测端点和请求参数，再保存。

自定义请求使用 POST，继承站点凭据与请求头，端点必须与 Base URL 同源。它覆盖当前模型的请求端点与参数，不会修改站点默认策略。

当前模型设置抽屉没有单独的“恢复继承”按钮。将内容手动改为与站点默认相同并保存，仍会保存为独立策略。

怎样使用请求参数表 ​

请求参数表支持添加、删除、启停参数，以及通过“粘贴 JSON”填写已有请求内容。

  • 文本、数字和布尔值应选用对应类型，避免把数字作为字符串发送。
  • 对象可添加子参数，使用对象路径组织嵌套字段；关闭父参数后，其子参数也不会发送。
  • JSON 类型填写合法 JSON，可用于数组或需要完整 JSON 表达的值。
  • 绑定“当前探测模型”的字段会随执行模型替换，预览里会显示当前模型或模型占位。
  • 导入 JSON 后先检查字段类型、模型绑定和请求预览，再保存。

参数是否被接受取决于服务商和模型。默认请求优先采用短提示、较少输出 Token；推理模型若只返回思考内容或输出被截断，可按服务商要求调整输出上限和推理参数。

试探一次和正式探测的区别 ​

“试探一次”出现在模型的自定义请求配置中，使用当前草稿发送真实请求。它不会自动保存草稿，不写入正式探测历史，也不推进模型健康状态。

确认草稿试探成功后，点击“保存”，再通过模型行“立即探测模型”或“探测已启用模型”发起正式探测。正式探测会写入历史并更新健康状态。

健康状态怎样判定 ​

状态含义
等待探测当前尚无可展示的正式探测结果
待确认已有结果，尚未达到稳定健康判定的阈值
正常已建立稳定健康状态，成功请求未达到慢阈值
偏慢成功请求的首 Token 或总耗时达到慢阈值
不可用连续失败达到“连续失败转红”阈值

已有稳定状态时，少量失败在达到阈值前会保持上一次稳定状态。红灯后需要达到连续成功恢复次数才会恢复；偏慢结果也计为成功。

尚无稳定状态时，默认阈值下连续失败未满 3 次会显示“待确认”；首次成功即可转为正常或偏慢。模型已经转红后，才需要连续成功 2 次恢复。一次失败会立即出现在探测记录里，但不一定立即让小面板转红。

成功与耗时的口径 ​

常规模型请求需要成功 HTTP 响应、有效回答正文，以及协议要求的完成标记。只有连接成功、HTTP 200 或思考内容，不能单独证明模型探测成功。

自定义 HTTP 请求按 2xx 状态和响应体完整读取判断，不要求模型回答格式。

流式首 Token 从请求开始计时，到第一段非空思考或回答文本到达为止；空增量、角色信息、心跳和工具参数不触发首 Token 计时。非流式和自定义 HTTP 请求的首 Token 显示为 —。
