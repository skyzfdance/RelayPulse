探测记录与 Token 统计 ​

入口：运行 → 探测记录。这里查看正式探测的单次请求结果；配置草稿试探和智商测试使用各自流程，不会混入这张正式探测记录表。

查找一条请求 ​

  1. 在时间范围中选择最近 24 小时、最近 7 天、最近 30 天或全部保留记录。
  2. 选择站点；需要时进一步选择模型。
  3. 用结果筛选“成功”“偏慢”或“失败”。
  4. 打开对应记录的详情。

列表支持分页。查不到刚才的结果时，先放宽时间、站点和模型筛选，再确认刚才触发的是正式探测。

阅读详情 ​

信息用途
本次请求结果确认这一次请求成功、偏慢还是失败
首 Token、总耗时判断响应开始速度和完整请求耗时
当次偏慢判定依据对照本次使用的阈值定位偏慢原因
输入、输出、总 Token查看服务商明确返回的用量
请求端点、策略、HTTP 状态、请求 ID确认实际连接与请求配置
请求详情查看已脱敏的请求头和请求体快照
原始返回查看响应头、接收数据块、错误响应及响应日志入口

请求快照和 JSONL 事件记录的是实际请求地址与已发送内容；访问凭据会脱敏。receivedTotal 表示累计接收的响应字节数，不是 Token 用量；Token 统计只读取服务商明确返回的 usage 字段。

记录保存的是当次请求事实。修改当前站点配置后，历史记录不会改写为新配置。本次请求结果也与当前模型健康状态分开记录。

例如，列表出现一条“失败”，小面板仍显示“正常”，可能是尚未达到连续失败阈值；先阅读当次错误，再核对健康状态规则。

查看 Token 统计 ​

切换到“Token 统计”，按时间和站点查看汇总。

RelayPulse 只汇总服务商响应中明确上报的 usage 数据，不根据回答文本长度估算。未上报的值显示 —，不应理解为零用量。

部分字段上报时，各列仅汇总已上报的值；“平均每次”只使用已上报总 Token 的请求。因此，不同统计列的有效样本可能不同。费用以服务商账单为准。

删除与清理 ​

  • 删除单条记录会删除该条正式记录及对应缓存文件，统计随之变化。
  • “清理全部探测记录”覆盖全部站点、全部时间范围，包含当前筛选之外的记录，同时清空对应 Token 统计。
  • 清理正式记录不会修改当前健康状态，也不会删除站点和模型配置。
  • 通用设置中的探测记录保留时间控制过期记录的自动清理；当前界面提供“保留 30 天”。

正式响应文件可能包含模型输出内容，分享排障材料前先检查正文。诊断包与这些响应文件的范围不同，见本地数据说明。
